# ДЗ №1–2 — Silent Courtyard

Проект Unreal Engine **5.8.1**, C++, на основе Third Person Template. ДЗ №2 продолжает ДЗ №1 в том же репозитории: PCG создаёт окружение, а охранник патрулирует, преследует игрока и расследует шум спринта через Behavior Tree.

## Запуск

1. Открыть `HW1.uproject` в Unreal Engine 5.8.1 и согласиться на сборку C++ модулей, если редактор её предложит. Для сборки нужен настроенный компилятор Unreal: Visual Studio с C++ на Windows или Xcode на macOS.
2. По умолчанию открывается карта `Content/HW2/Maps/L_HW2_PCG`. Нажать **Play** и щёлкнуть по игровому окну.
3. Состояние охранника и расстояние до него показаны сверху слева. Игрок появляется у южной стороны двора, охранник — у северной.

Карта, Blackboard, Behavior Tree и PCG Graph уже сохранены в `Content/HW2`: запускать генератор ассетов перед игрой не требуется. Исходная карта ДЗ №1 сохранена в `Content/ThirdPerson/Lvl_ThirdPerson`.

| Управление | Действие |
|---|---|
| W, A, S, D | Движение |
| Мышь | Камера |
| Space | Прыжок |
| Left Shift, удерживать | Спринт; при движении по земле создаёт шум |
| E | Взаимодействие из ДЗ №1, событие `OnInteraction` |

## Базовая часть ДЗ №2

- **PCG:** граф `PCG_Obstacles` содержит стандартные узлы Create Points Grid → Transform Points → Static Mesh Spawner. Сетка из 24 точек получает воспроизводимые случайные смещения, повороты, размеры и материалы. Seed компонента — `21124`. Все 24 укрытия созданы PCG; вручную сформированы только основание, границы и разметка двора.
- **Навигация:** `NavMeshBoundsVolume` покрывает двор; у PCG-мешей включены `BlockAll` и влияние на навигацию. NavMesh построен и сохранён; включено динамическое обновление при изменении геометрии.
- **Персонаж ИИ:** `AHW2AICharacter`, контроллер `AHW2AIController`, восприятие через AI Perception (Sight + Hearing).
- **Blackboard:** `BB_Guard`; дерево `BT_Guard` управляет всеми запросами перемещения и переключением ветвей. Контроллер передаёт в Blackboard результаты восприятия.
- **Патруль:** случайная достижимая точка в радиусе 600 см от исходной позиции, движение со скоростью 250 см/с, пауза 1 с.
- **Погоня:** видимый игрок прерывает патруль или расследование. Скорость 620 см/с. Обнаружение на 1300 см, потеря по дистанции на 1600 см, половина угла обзора 70°. Препятствия перекрывают видимость. Если игрок находится на недоступном для навигации укрытии, охранник сохраняет погоню и повторяет попытку через 0.8 с, не переключаясь ошибочно на патруль.
- **Потеря цели:** ключ цели очищается, погоня прерывается, охранник возвращается к патрулированию вокруг исходной точки.

Приоритеты дерева:

```text
Selector
├─ TargetActor задан [Observer Aborts: Both]
│  └─ Selector: (Move To TargetActor → Wait 0.3) или Wait 0.8 при недоступной цели
├─ HasNoise = true [Observer Aborts: Both]
│  └─ InvestigateNoise: место звука → поиск области
└─ Sequence: FindPatrolPoint → Move To PatrolLocation → Wait 1
```

| Ключ Blackboard | Назначение |
|---|---|
| `HomeLocation` | Исходная точка патруля |
| `PatrolLocation` | Следующая достижимая точка патруля |
| `TargetActor` | Игрок, подтверждённый зрением |
| `HasNoise` | Есть неисследованный шум |
| `NoiseLocation` | Зафиксированное место звука |
| `SearchRadius` | Неопределённость позиции звука |

## Усложнение для 9–10 баллов: расследование шума

Спринт из ДЗ №1 связан со слухом охранника. Событие шума возникает не чаще раза в 0.55 с, только при фактическом движении по земле со скоростью более 100 см/с. Удержание Shift на месте, прыжок и обычная ходьба шум шагов для ИИ не создают. Радиус слышимости — 2400 см.

Усложнение реализовано в собственном C++ узле **`UBTTask_InvestigateNoise`**:

1. Охранник запоминает позицию звука и идёт к ней со скоростью 300 см/с. Текущее положение скрытого игрока ему не передаётся.
2. Радиус поиска растёт от 160 до 650 см с расстоянием до источника звука.
3. После достижения места звука охранник проверяет до четырёх случайных доступных точек в этой области с короткими паузами.
4. Точки проецируются на NavMesh; частичные маршруты запрещены. Неудачный маршрут приводит к попытке выбрать другую точку.
5. Новый звук может перенаправить поиск, но не продлевает общий лимит времени. Номер события защищает свежий звук от ошибочного удаления завершившимся поиском.
6. Весь поиск ограничен 16 с и 18 попытками перемещения. После завершения или исчерпания лимита охранник возвращается к патрулю.
7. Подтверждённая зрением цель немедленно прерывает поиск. При отмене узел снимает подписку с завершения пути и отменяет только собственный запрос движения, чтобы не остановить начавшуюся погоню.

Узел имеет отдельный экземпляр для каждого охранника. Базовый `UBTTask_FindPatrolPoint` также написан на C++; основное усложнение составляет многошаговый `InvestigateNoise`.

## Как проверить вручную

1. **Патруль:** не приближаться к охраннику. Он ходит по северной части двора и делает паузы.
2. **Шум без видимости:** подойти примерно на 15–22 м, держась за укрытиями, и пробежать с Shift. Состояние станет `INVESTIGATE`. Отпустить Shift, тихо уйти в сторону и наблюдать, как охранник обследует место звука.
3. **Поиск:** оставаться вне видимости и не создавать новых звуков. Охранник обходит точки в области, затем возвращается к `PATROL`.
4. **Прерывание:** во время расследования выйти перед охранником в пределах 13 м. Состояние сменится на `CHASE`, он начнёт преследование.
5. **Потеря цели:** убежать дальше 16 м или скрыться за укрытием. Состояние вернётся к `PATROL`.
6. **PCG и NavMesh:** остановить Play, выбрать `PCG - seeded courtyard cover`. Изменение Seed и кнопка Generate меняют расположение укрытий. Клавиша `P` в редакторе показывает навигацию, огибающую их.
7. **Дерево:** открыть `BT_Guard`; во время Play выбрать работающего охранника в списке отладки и наблюдать активные ветви и значения Blackboard.

## Автоматическая проверка и воспроизведение ассетов

При запуске игры с параметром `-HW2Verify` включается проверка в настоящем игровом мире. Она проверяет работу дерева и PCG, реальное движение патруля, привязку патруля к дому, отсутствие шума неподвижного спринта, слух при движении, завершение расследования, прерывание поисковой ветви зрением, движение погони и возобновление патруля после потери цели. В обычной игре эта проверка не создаётся.

Пример macOS после сборки `HW1Editor` (заменить пути на свои):

```bash
"/path/to/UE_5.8/Engine/Binaries/Mac/UnrealEditor-Cmd" \
  "/path/to/un_HW1/HW1.uproject" /Game/HW2/Maps/L_HW2_PCG \
  -game -HW2Verify -NullRHI -unattended -nosound -stdout
```

Результат находится в логе: `HW2 VERIFY RESULT: PASS` или `FAIL`, а также в `Saved/HW2Verification.txt`. Проверка автоматически завершает игру. Ориентироваться нужно на этот результат: Unreal на macOS может возвращать код процесса 0 и при завершении неуспешного теста.

Редакторский модуль `HW1Editor` содержит командлет `-run=HW2Build`, которым были созданы сохраняемые ассеты. Он заново создаёт учебную карту, дерево, Blackboard и PCG-граф; запускать его после ручных изменений этих ассетов следует только если нужно восстановить исходную конфигурацию. Этот модуль не входит в игровую сборку.

## ДЗ №1

Сохранены персонаж от `ACharacter`, Enhanced Input, спринт, Blueprint-подписка на динамический multicast-делегат `OnInteraction`, сообщение `Interaction triggered!`, состояние Sprint в Animation Blueprint и выносливость на C++.
